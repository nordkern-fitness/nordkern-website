# NORDKERN FITNESS 8.5 – REPRODUZIERBARE CHROMIUM-BROWSERTESTS

Stand: 20. November 2026. Website-PR #3, Entwicklungsbranch `fix/hash-navigation-safety-2026-11-12`. **Kein Produktionsdeploy.**

## Lokal ausführen

Voraussetzungen: Node.js 22, Python 3, Playwright-fähiges Betriebssystem, Browserdownload möglich.

Vom Repository-Hauptverzeichnis:

```bash
npm install --no-save --no-package-lock @playwright/test@1.56.1
npx playwright install chromium
npx playwright test --config browser-tests/playwright.config.cjs
```

Für Ubuntu 24.04 CI kann zusätzlich `npx playwright install --with-deps chromium` verwendet werden. Der Playwright-Webserver startet automatisch `python3 -m http.server 8765 --bind 127.0.0.1` im Repository-Hauptverzeichnis. Die Browserseite ist `http://127.0.0.1:8765`; kein echter Supabase-Login notwendig oder erlaubt.

## Tatsächliche Prüfumgebung

- Echte Chromium-Engine, drei Projektionen: Smartphone-Profil iPhone 13 (in Chromium emuliert, **kein Safari-/iPhone-Test**), Tablet 820 × 1180, Desktop 1440 × 900.
- Webseite wird inklusive realem HTML, CSS und JavaScript über lokalen HTTP-Server geöffnet. Playwright führt echte Klicks, Tastatureingaben, Fokuswechsel und Formular-Submits aus.
- `browser-tests/fixtures.cjs` fängt alle Requests auf `mfaqlfsaatmhvcqlpzoz.supabase.co` im Browser ab und ersetzt sie durch isolierte kontrollierte Antworten. GoTrue-Login, Signup (keine echte User-Erstellung), Kontodaten, Tarifliste, Mitgliedervertrag, Bestellungen, Shop, Gerät und Sperr-RPC werden so als UI-Flows getestet. Externe Font-Requests werden blockiert; es findet kein Kontakt zu realen Zahlungs- oder Supabase-Diensten statt.
- 10 Szenarien pro Projekt, insgesamt 30: Start → Tarife inklusive Tastatur; Signup ohne automatische Freigabe; Login-/Formularfehler; Vertrag/Guthaben/Orderfilter/Refresh; digitaler Warenkorb und Menge; Gerätesperre inklusive Dialog und Logout; Shop-Fehler/Leerzustand; Quer-Scrollen auf fünf Kernseiten; sichere Website-App-Links; echte AGB/Datenschutz-Tabs.
- Der Browser-Workflow liegt in `.github/workflows/browser-e2e.yml`; HTML-Bericht und eventuelle Fehlerscreenshots unter `playwright-report/` und `playwright-results/`, im Browser-CI-Artifact archiviert. Die reguläre statische Website Quality CI bleibt unabhängig aktiv.

## Nachweise und Fehlerbehebung

- Erster Browserlauf: GitHub `ubuntu-latest` (Ubuntu 26.04) nicht kompatibel mit der für 8.5 gepinnten Playwright-Version; in eigenem Workflow auf Ubuntu 24.04 geändert.
- Lokale Testserver-Pfadabweichung korrigiert (`cwd` Repository statt `browser-tests/`); optionale Google-Fonts-Aufrufe im isolierten Test blockiert, ohne die Seite zu verändern.
- Der **echte Browsertest** fand einen fehlerhaft doppelt escapten E-Mail-RegEx in `js/account.js`: gültige Registrierungsadressen wurden abgelehnt. Korrigiert und in `tests/account.test.cjs` gesondert abgesichert.
- Registrierung hatte zuvor fälschlich auf Hash-IDs statt Tab-Namen in den rechtlichen Informationen gezeigt. Echte Tabs sind `impressum.html#agb` und `#datenschutz`; im Browser getestet.
- `30 passed (24.3s)` auf der vorletzten Testfassung; der erste Workflow blieb danach **nur** wegen eines nicht gefundenen Berichtspfads rot.
