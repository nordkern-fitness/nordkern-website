## 2. Neue Web-Codekorrekturen

In `js/account.js` schützt jetzt eine einzige Fail-Closed-Bereinigung alle privaten Portal-Inhalte bei Token-/Rechtefehlern oder Profil-Deaktivierung. Ein doppelter Refresh-Aufruf benutzt dieselbe laufende Erneuerung; ein verzögerter Refresh kann nach Logout oder Benutzerwechsel keine alte Sitzung reaktivieren. Server-401/403 invalidieren lokal gespeicherte Anmeldedaten und verstecken Vertrags-/Wallet-/Bestell-/Gerätekarten. Gültige Auth-Responses werden weiter an die ursprüngliche User-ID gebunden. GoTrue-Fehler für nicht bestätigte E-Mail und Rate Limits erhalten verständliche Texte ohne interne Fehlermeldungen. Bei Ausfall des **öffentlichen** Tarifkatalogs bleiben die bereits autorisierten persönlichen Vertragsdaten sichtbar und der Checkout deaktiviert.

## 3. Reale private E2E-Stufe – nur ausdrücklich freigegebene DEV-Testmitglieder

Die separate Datei `browser-tests/live-member.member.cjs`, die Konfiguration `browser-tests/live-member.config.cjs` und der **nur manuell** gestartete Workflow `.github/workflows/browser-live-member.yml` sind implementiert, aber **nicht als grüner echter Login-/Registrierungsnachweis zu werten**. Keine Test-Credentials wurden angelegt, geraten, aus vorhandenen Konten extrahiert oder zum Logging verwendet.

Für einen zulässigen Lauf müssen die Verantwortlichen zuerst ausschließlich in `nordkern-dev` isolierte Mitgliederprofile/Test-Mailadressen bereitstellen, die über RLS die eigene Kontoansicht sehen dürfen und deren Verwendung ausdrücklich freigegeben ist:

- GitHub Repository Variable `NORDKERN_E2E_ENABLED` genau `I_CONFIRM_DEV_TEST_USERS`.
- GitHub Actions Secrets `NORDKERN_E2E_EMAIL` und `NORDKERN_E2E_PASSWORD` für das ausdrücklich freigegebene **erste Testmitglied**. Keine Secrets in einem `EXPO_PUBLIC_`-Wert oder im Repository speichern.
- Repo Variable `NORDKERN_E2E_ACCOUNT_ID` = erwartete UUID dieses DEV-Testmitglieds; zusätzlich **zweites isoliertes Testmitglied**, dessen UUID als `NORDKERN_E2E_FOREIGN_ACCOUNT_ID` für die Cross-Account-RLS-Probe hinterlegt wird.
- Workflow **manuell** über GitHub Actions auslösen. Ohne Variable ist der private Job absichtlich nicht lauffähig; ohne benötigte Credentials stoppt die Konfigurationsprüfung. Keine heimlichen Fallback-Konten.
- Die private Stufe prüft tatsächlichen Login, Identitätsabgleich, eigene Vertrags-/Guthaben-/Bestellansichten, Refresh, Logout, erneute Anmeldung erforderlich, und bei zweiter Test-UUID, dass fremde Profile, Verträge, Wallets, Orders, Studioauswahl über echte RLS-Abfragen nicht gelesen werden können. Keine Vertrags-, Shop-, Stripe- oder Geräteschreibvorgänge. Bildschirmaufnahmen, Videos und Traces **deaktiviert**, keine Token-Logs.

**Registrierung und Mailbestätigung sind weiterhin blockiert:** Es fehlt ein ausdrücklich freigegebenes Einmal-Testpostfach mit erreichbarem Inbox-Zugriff, und ein abgesicherter Prozess zur Entfernung der angelegten DEV-Testuser-/Profildaten. Derzeit wird aus Sicherheitsgründen **kein** Konto neu angelegt. Vor einem tatsächlichen Registrierungstest muss ein separates, einmaliges DEV-Mailpostfach samt Mailzustellungsprüfung und Löschfreigabe bereitstehen. Bestehende Konten bleiben unangetastet. Für die Entsorgung nur die **zu den Test-UUIDs** gehörigen isolierten Accounts mit bestätigtem Owner-Entscheid über das Supabase-Dashboard entfernen; zunächst aktive Test-Sessions/Token widerrufen und anwendungsseitige Testdaten kontrolliert prüfen. Niemals sämtliche DEV-Daten löschen.

## 4. Reproduzieren

Von der Website-Wurzel auf Node 22 und Ubuntu 24.04:

```bash
npm install --no-save --no-package-lock @playwright/test@1.56.1
npx playwright install --with-deps chromium firefox webkit
npx playwright test --config browser-tests/live-public.config.cjs
```

Der Webserver startet bei Bedarf automatisch lokal über Python. **Dieser Aufruf verbindet sich mit der tatsächlichen DEV-Domain**; kein Mock-Layer. Alle Requests sind schreibgeschützt. Der bereits bestehende Mock-Workflow lautet separat:

```bash
npx playwright test --config browser-tests/playwright.config.cjs
```

Nur für explizit eingerichtete private Testkonten und nach manueller Freigabe:

```bash
npx playwright test --config browser-tests/live-member.config.cjs
```

Die privaten Konfigurationswerte müssen dabei vorher als Umgebungsvariablen bereitgestellt werden. Die Repository-CI startet diesen Test **nicht automatisch**.
