# Nordkern 9.1 – Public exposure / privacy and legal release boundary

**Checked:** 24 November 2026. **Scope:** public `nordkern-fitness/nordkern-website`, branch `main` and PR #3, private App PR #4. No DNS, Pages, live site, visibility, repository history or legal text was changed.

## Verified public exposures

- `impressum.html` contains **six** occurrences of the founder's legal name in the provider/representative, controller and terms sections on both public `main` and the website PR branch. Names are intentionally not duplicated in this report. This is personal information in a public Git tree and its revision history.
- The same legal source still contains **placeholder street address and postal town**. A live commercial site using this as its final legal notice must be reviewed for compliance. Replacing the natural-person provider with the brand alone, inventing an address or silently removing the legal section is prohibited.
- Website repo visibility: **public**, with accessible `main`, `fix/hash-navigation-safety-2026-11-12`, `reboot/nordkern-unified-design` and `refine/pricing-layout-2026-11-02` branches. Git source and previous commits remain reachable. App repo visibility is **private**. Neither setting was changed.
- Sampled the **latest 300 public `main` commits** (three pages): author names used the brand designation rather than the founder's personal full name. Older Git metadata, forks, archives, search caches and third-party copies are not claimed to be exhaustively absent. Some historical commit author email addresses are not on the branded domain; their privacy and provenance require a separate owner review before any history operation.
- The `main` site has a `CNAME` for `nordkern-fitness.de`; repository metadata reports GitHub Pages enabled. The precise Pages deployment source and the current domain HTML could **not** be independently verified with these tools. No assertion of which revision is live.
- The website CI was publishing double-clickable **preview artifacts and full-source ZIP copies** on public PRs; the unmodified preview builder duplicated the entire legal page. This made accidental redistribution easier even though the source already remained public.

## Implemented *only in the website PR development branch*

1. `scripts/build_preview.py` writes a clearly labeled **offline preview-only** notice in place of the copied legal source, linking to the unchanged published imprint. It is not a replacement legal page on GitHub Pages, and does not change `impressum.html` in source or `main`.
2. `scripts/privacy_audit.py` extracts the legal name at runtime from the preserved `Vertreten durch` field and checks Git-tracked text files for additional occurrences. It never embeds or logs the name. It separately rejects leaked names in generated preview files. Fictional-name unit tests cover expected/negative behavior.
3. `.github/workflows/website-quality.yml` enforces the guard before and after preview generation. Public PR CI no longer automatically uploads extra full-source ZIPs; manual source export remains possible. Preview retains a link to the unchanged live imprint.
4. No source name removal, legal substitutions, Git history rewriting, public Pages publishing, DNS changes, privacy settings changes or new business assertions.

## Owner/legal review, before public commercial use

**§ 5 DDG** may require the true operator name and full service address when a service is business-like. Verify whether the current offering is already commercial, the required legal provider identity and notice, acceptable privacy-preserving registered service address, truthful pre-founding status, data controller, contract and marketing claims, studio-operation status and company form. A legal professional must approve any replacement before promotion to `main`. Historical public data may remain copied or indexed even after later approved changes.

The immediate outcome reduces **new copies**, not the original public name exposure. Real remediation requires a separately approved legal and publishing decision.
