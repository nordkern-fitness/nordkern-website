# 9.2 – Private development transition (prepared, NOT executed)

Target: both repos private; unpublish the public commercial website until legal clearance; retain domain. Use loopback preview, not public Pages. GitHub Free supports private repos, but Pages from private organization repos needs a qualifying plan. Access-controlled private Pages requires Enterprise Cloud. Verify actual plan and settings first.

## Approval and change order
1. Record Pages source, domain verification, DNS web records/TTL (including www), HTTPS, collaborators, rulesets, forks, Actions settings/usage and PR #3 head/base. Make encrypted offline git bundle --all, verify and test restore; save PR metadata/settings separately. Keep registration and email MX/TXT intact.
2. Obtain legal clearance for suspending the offer, existing contracts/support, data retention, GDPR and §5 DDG. No anonymous commercial placeholder or invented provider. Even a marketing splash may require an imprint.
3. With explicit DNS/hosting approval, coordinate removing or replacing website DNS records with a controlled destination; avoid dangling Pages mappings. Preserve mail/verification. Remove Pages custom domain and unpublish in Settings > Pages; stop automatic publish sources. Test signed-out access to domain, github.io and deep URLs.
4. With explicit visibility approval, set existing website repo private (Settings > Danger Zone). Verify signed-out repo/raw access denied; authorized user still has branches, PR #3 Draft, CI and connector. Recheck plan/minutes/rulesets/security features. Public forks detach and remain public; stars/watchers may be lost; historical clones/artifacts/caches persist. No history rewrite.
5. Internal preview: python3 scripts/private_preview.py ; open http://127.0.0.1:8765/VORSCHAU-STARTEN.html ; stop Ctrl+C. Loopback, exact Host, no directory listing, no-store/noindex, restrictive CSP blocks API and form submits. No multi-user auth; no LAN/tunnel. Do not follow external links or enter personal data. Functional flows use isolated E2E. Public CI no preview/source upload; private manual dispatch only. Previous artifacts unchanged.
6. Set repository-local git user.name to brand, user.email to verified GitHub noreply or approved brand identity; enable GitHub email privacy and blocking pushes exposing private email. Inspect author and committer before pushing; CI detects after publication. Review forks/caches separately.
7. Rollback: keep source private and stop local server. For public return, legal and owner approval first, publish reviewed static release to approved separate host (no private history/logs/docs); verify TLS/domain then DNS. Restoring original repo public requires separate approval and complete review of history/logs first. Restore saved settings/source/DNS in safe order. Some visibility effects are irreversible.
